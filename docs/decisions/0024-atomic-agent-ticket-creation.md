# ADR-0024：复用工单业务的原子Agent建单

日期：2026-11-21。接续Customer009与操作专属许可，下一子批次只实现Java业务事务和回执读取，不同时接模型Loop、HITL、公开API或默认路由。复用TicketService.createFromChannel及既有工单号/SLA/业务事件/客户动态/工单数/标签逻辑，不用SQL另写第二套工单业务，不伪造坐席LoginUser。

工单VO没有内部ID，业务层创建后需按同租户唯一编号取回并核对关键字段。为避免把其他渠道的旧工单误当本Run结果，拟将现有渠道创建体抽为共同内部方法：旧渠道保持creator/editor=channel，新Agent窄方法使用agent-run:{runId}。只复用既有creator/editor列，不加第二套工单字段或编号/SLA实现；新回执前再核Run标记、当前会话/客户、固定策略及原文。该小范围抽取需要保留旧渠道行为回归。

拟定ticket-create-v1参数只含可信tenant/event/run/snapshot与有限非空title/content。模型不可传客户/会话/租户、优先级/类别/指派人或平台工单类型；业务策略固定内部工单、优先级2、类别5、会话来源渠道1、无指派。客户/来源会话只从当前来源事务读取，客户名称不向模型暴露。标题≤128码点/512 UTF-8字节，正文≤8192字节，无NUL/非法Unicode；保持原文，不静默截断或规范化。参数SHA域隔离，包含引用、标题/正文Hash及固定策略。

业务事务要求先绑定可信租户，限定锁/语句时间；按tenant/run取得事务advisory lock。匹配已提交回执只返回既成事实引用，参数或来源冲突拒绝；无回执时必须校验TICKET_CREATE许可的所有引用/Hash、当前来源会话/访客/消息/快照及关联客户。业务调用与回执同事务，许可在DB时钟写前/写后重验，失败回滚全部本地业务行/事件。不得在事务内调用模型/授权HTTP或其他无界网络。

查询回执只确认某tenant/event/run已提交的创建事实，可在任务终态/来源过期或接管后核对，不返回工单正文/客户信息，也不授予新的执行资格。找不到回执不证明先前请求一定未提交；SDK/Runtime未知结果恢复属于后续批次，不允许盲重试。created_at是数据库记录时间，不冒充精确提交时间或外部送达证明。

验收采用真实受限PG与实际TicketService/mappers，核业务字段/SLA/事件/客户统计只生效一次；同Run并发/参数冲突/来源撤权或TTL/操作混用/过期许可/事务末尾失败回滚；读回执不触发二次业务。关联客户直接取得UPDATE行锁，避免先SHARE再升级导致同客户竞争；仍有2秒锁超时，不宣称所有旧业务锁顺序均无死锁。

实际结果：4项新参数/事务单元测试通过，连同既有操作/回复参数共11项；新16项真实PG通过，客服专项合计129项、Python KB19项通过。包含8路同Run创建只生效一次、实际业务返回后篡改结果/快照过期/许可过期全部回滚、128码点emoji标题与8192字节正文原样存储。全模块Maven verify通过。原始日志、失败夹具与完整业务验收另见reliability-verification.md。8路样本验证幂等，不是吞吐或延迟测试；可选标签处理沿用既有best-effort策略，不承诺所有标签刷新必然成功。

本批仅Java业务边界，尚无公开API、Python SDK、模型WRITE工具、HITL或工单未知写核销。回滚不注册新入口，保留既有渠道路径及已提交工单/回执/历史/预算，不删Customer009或放宽权限。
