# ADR-0068 坐席取消已批准的工单任务

管理员或主管可在工单审批窗口提交取消请求。客服服务绑定当前登录人、租户、已投递的会话来源、任务和快照，通过内部签名端点发送取消命令。读取响应前重新检查来源。只有持久化记录表明已批准的工单任务可以进入此操作。尚待审批的提案沿用拒绝入口。

Runtime 在原任务行锁内处理取消与完成。已经结束的任务返回实际终态，重复请求不追加第二个终态事件。无写入步骤时取消会结束任务并关闭仍有效的批准，失效 Worker 无法继续提交。写入已在 Runtime 确认时保留执行权，Worker 可以继续完成收尾。写入已经发出但尚无确定结果时，任务结束并保留待人工核查标记。已有工单、回执和通知保持原样，可用现有的只读回执核销流程确认原写入。

审批关闭时记录服务端解析的坐席身份。审批已消费时沿用执行状态、取消标记、终态事件和既有核销审计。坐席能从取消响应或之后的授权进度读到脱敏写入状态。前端对取消操作单独确认，响应丢失时提示先查询进度。当前授权在请求前后分别核验，取消在两次核验之间完成时，失效来源只会收到拒绝响应。

## 复现与回退

- 在仓库根运行 `mvn -B -f backend/pom.xml verify`、`python scripts/test-customer-rls.py --with-ai` 及 `python scripts/test-agent-runtime.py --with-java-delivery`。定向测试覆盖取消与完成竞争、重复请求、来源不匹配，以及实际工单已提交但 Worker 尚未收到确认。
- 在 `frontend` 运行 `npm run test:browser` 和 `npm run build`。受控 HTTP 夹具验证确认入口、终态、人工核查与响应丢失。
- 依次升级客服服务、AI 服务和前端。应用回退依次恢复前端、AI 服务和客服服务，保留事件、回执及核销记录。无需数据库迁移。
