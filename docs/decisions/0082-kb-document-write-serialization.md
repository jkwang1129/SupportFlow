# ADR-0082 知识文档写入按文档串行

知识文档原先先读正文与索引状态，写入时才取得 PostgreSQL 行锁。并发编辑提交后，排队的重新索引仍可使用旧正文。发布也可能依据等待前的索引状态通过判断。

编辑、重建索引、变更发布状态和删除共用带租户、文档 ID 和软删除条件的 `FOR NO KEY UPDATE` 查询。写事务先取锁再读初始状态。PostgreSQL 在默认的 `READ COMMITTED` 下等待前一写事务结束，再基于当前提交行计算。现有文档权限和 RLS 继续生效。不同文档互不争用这把行锁。普通详情、预览和检索保持原有读路径。

删除的软删除标记和切片删除由同一个 Java 数据库事务完成。移除原有同步 AI 删除请求，避免另一个数据库事务等待当前已删除切片的行锁。AI 已有切片维护接口照常工作。

Java 仍管理文档台账，AI 仍使用独立事务替换切片。锁仅协调经客服服务发起的同文档写入。它依赖现有有界索引请求，支持等待中的操作读到最新提交正文。AI 已写入而 Java 未提交的故障窗口、历史切片快照和索引回滚仍需独立处理。

在已安装 JDK 25、Maven 和 Docker 的仓库根目录执行 `python scripts/test-customer-rls.py --with-ai`。回归使用隔离的 PostgreSQL 17、租户运行账号，并让两笔事务真实争用行锁。索引响应使用固定替身，切片仍在另一个真实事务提交。

回滚可还原本批 Java 代码，无数据库迁移。回滚期间按文档串行安排编辑、重新索引和发布，对有疑问的文档用当前正文重建索引后复核再发布。
