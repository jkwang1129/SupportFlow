# ADR-0029 工单未知写的终态核销

显式可信宿主通过 `TicketReconciler` 确认历史工单提交。入口只处理 `FAILED / SIDE_EFFECT_UNKNOWN` 且仅有一个 `UNKNOWN` 工具写步骤的任务。步骤必须绑定 `ticket.create`、`ticket-create-v1`、原主体、来源快照和参数摘要。并发观察者的结果以数据库事务为准。

核销先检查本地审计，随后在数据库事务外执行一次签名回执 GET。请求以原租户、来源事件和任务为边界，并带原快照和摘要作为本地核对条件。回执缺失、服务异常或绑定不一致时，任务继续阻断同会话的后续来源。审批、撤销和工具调用继续使用各自的入口。

确认时在短事务中锁定任务及步骤，校验观察到的令牌、来源和步骤原参数，与取得回执前的记录比对。使用核验过的业务引用追加 AI005 审计、将原写步骤标为 `SUCCEEDED`、把任务错误改为 `SIDE_EFFECT_CONFIRMED` 并递增令牌。任务保持 `FAILED`，保留取消标记、完成时间、已有预算及执行次数。已核销的同一事实直接返回历史审计，旧写授权继续失效。

复用回复核销的观察和事务规则，保留原回复入口与 AI004 账本。工单操作使用独立的候选类型、回执类型及 AI005 账本。多次副作用的任务仍需独立恢复方案。回滚时停用可信宿主的工单核销调用并保留业务回执、审计和历史令牌。

65 项定向数据库测试通过，覆盖 19 项工单确认、21 项回复确认和 25 项账本约束。真实 Java、AI 与受限 PostgreSQL 链路确认两个历史工单，每案只增加一次 GET，后续同会话任务恢复领取。无回执的任务继续阻断。原始结果与复现命令见 [阶段验收](../reliability-verification.md)。
