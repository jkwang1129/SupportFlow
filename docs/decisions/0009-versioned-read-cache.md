# ADR-0009：可变只读结果按当前授权版本复用

日期：2026-11-20。工单工具v1已能阻止旧缓存冒充当前状态，但合法状态变化会使整个Run失败。保持来源快照不可变策略，单独为可变只读资源新增current-version缓存政策，不改执行表、数据库或业务权限。

ReadTool默认仍immutable；current-version必须由可信注册代码选择，模型参数不能覆盖。先以固定逻辑键创建INTERNAL/NONE参数绑定Step，绑定工具名/版本/主体/参数SHA，恢复时改变参数在新鉴权前就拒绝。此锚点消耗一次总Step预算，无模型/工具调用；不会为了换缓存版本绕过原逻辑请求约束。

之后每次新预留TOOL/READ完成当前业务授权。证据必须有明确资源引用和64位小写Hex的当前资源版本摘要；只有布尔True或缺摘要不够。成功后以“逻辑键+本次授权引用”的SHA作为正文步骤键：当前版本相同复用已成功正文，版本改变则预留新TOOL/READ后重新读取和原子存正文。当前返回或缓存仍须通过Schema、资源绑定与本次证明核验。只读失败仍沿用原Run重试/租约/取消/模型和工具总预算，没有内部无限刷新循环。

新状态和原状态的正文分别保留可审计记录。首次通常消耗3个总Step（绑定+授权+读取）/2次工具预算；恢复不变消耗新授权1Step/1Tool，变化另加读取1Step/1Tool。预算不够时在实际调用前明确失败，不把授权结果中的新事实免费交给handler，也不清空计数。反复访问相同/不同缓存版本照样需要当前授权并消耗预算。

工单工具执行版本提升为ticket-status-v2；业务HTTP与结果schema仍ticket-status-v1，没有改Java或SQL。新Registry拒绝旧v1提案，不把已记录旧工具计划静默当成v2执行；本项目尚未自动启动业务Worker，因此无在途生产计划迁移。后续部署若需兼容旧计划，须保留对应Runtime/工具版本，不能修改已持久化意图。

若资源恰在当前授权和新读取之间再次改变，结果与证明不一致仍明确失败，不无限重试；这批只解决“恢复时已有新版本”场景。授权是读取时点，不承诺内容在网络传输/模型思考期间永不变化。写操作继续用业务写许可/回执，current-version从不用于未知WRITE重放。

回滚停用v2注册或关闭read-tools开关，保留绑定/授权/各版本正文与Run预算；不要把v2计划指向v1代码，也不删除UNKNOWN/计数。原来源工具immutable政策和旧Workflow不受此策略切换影响。物理保留/容量治理、完整上下文策略、模型循环/HITL仍属后续。
