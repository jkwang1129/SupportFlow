# ADR-0070 旧客服 AI 月预算闸门

旧客服入口在发送 AI 请求前查询租户预算。Ops 每次从数据库读取预算。已启用正数预算的租户还需取得 AI 服务返回的同租户、同统计窗口用量。缺少有效用量或预算查询失败时，内部接口返回 HTTP 503。无预算、已禁用或预算为零时继续不限额。达到预算时用金额判定，百分比四舍五入仅用于显示和预警。在达到预算时保留仅告警、降级和暂停三种配置。

客服服务按租户在进程内合并并发刷新。已确认的判定从收到时起缓存 5 秒，刷新失败的降级结果缓存 1 秒。若上一次已确认暂停，刷新失败期间保持暂停，直到取得新判定。冷启动查询失败时进入降级。缺少合法业务租户时直接降级。缓存和暂停记忆随进程重启清空。客服到 Ops 的连接和读取等待分别为 250 和 1200 毫秒，Ops 到 AI 的等待分别为 200 和 700 毫秒。这些是客户端连接和读取超时配置。

此策略复用客服大脑、知识问答、图片识别、质检以及语音识别与合成的既有降级路径。客服大脑降级时返回提示，暂停时转人工，这两种路径都跳过模型与调用计数。预算页面和告警读取沿用原接口。Runtime 的调用前金额预留与结算继续由 [ADR-0050](0050-tenant-model-cost-reservations.md) 覆盖。

## 验收与回退

- 用 JDK 25 执行 `mvn -B -f backend/pom.xml verify`。客服测试使用回环 HTTP 和可控单调时钟，覆盖失效、恢复、同租户并发合并及故障期间的模型与计费调用。
- 执行 `python scripts/test-security-flow.py`，在隔离 PostgreSQL 中通过实际 Ops、AI 服务验证金额边界、租户隔离、策略即时切换和权限恢复。合成账目只用于验证执行行为。原始 HTTP 判定保存在 `.local/verification/legacy-cost-guard.json`。
- 滚动发布时先更换客服服务，再更换 Ops。两者都切换后才具有完整的故障策略。直接回退到旧版本会恢复长缓存及失败放行，需由部署方评估超预算风险。无数据库迁移。

月度用量仍使用已有 AI 计量账本和部署时区。独立客服实例可持有各自最近一次判定，落账间隔和并发在途调用会带来额外偏差。真实供应商账单对账、生产容量和并发消费上界需单独验收。
