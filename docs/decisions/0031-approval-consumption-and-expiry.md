# ADR-0031 审批消费与过期发现

获批的工单任务通过已有 ToolExecutor 和真实工单 API 继续执行。恢复时加载原参数，通过固定工具范围重新核验来源。Write Step 预留、调用预算增加和审批消费在同一 AI 数据库事务提交。许可只发给被消费记录绑定的 Step，期限取审批、租约、任务截止时间和短许可窗口的最小值。截止、撤销和批准由 Run 行锁排序，已消费的步骤沿用现有取消与未知结果控制。

已成功写入的任务在恢复时用原 Step 和收据确认，保留已经消费的审批及原预算。批准后参数变化、其他来源快照、过期、缺失消费标记或新 Step 试图复用同一审批，均拒绝获得写许可。新旧工单策略继续由可信宿主显式选用。审查入口应绑定现有坐席身份和角色，当前控制面方法只接受已解析的可信身份。

下一子批次把过期审批纳入现有 Worker 租户发现和有界领取。数据库只返回有待处理工作的租户代码。每轮在当前租户范围内选择有限个过期 Run，按 Run 再 Approval 的锁顺序处理，保留原决定与预算。等待态或获批但未消费的过期任务解除会话阻断，已消费的未知写继续按回执核销。到期处理和审查入口是独立测试和发布单元。
