# ADR-0001：客服计费批次与可靠重报

日期：2026-11-19。关联 PR-6。基线 `611f44d`。

## 问题与边界

日统计 UPSERT 不是增量批次去重。客服 `BillingUsageReporter` 取走内存计数后网络失败即丢失；HTTP 200 也可能是业务拒绝。当前内部上报没有服务认证。网关请求量实际进入 tenant-service 的另一张日统计表，不直接调用 billing；该链路后续单独改造，不能把客服补丁当成网关也完成。

## 决策

- 不新增 MQ。用 billing_db 的唯一 `(tenant_code,batch_id)` 处理账本，在同一事务中登记批次并累加统计。相同批次/相同内容幂等成功；内容变化返回冲突。固定业务日期、非负数和规范化小数参与 SHA256；不把调用时间作为重试时的新业务日期。
- 客服在 customer_db 保存待发批次。每租户最多一条持久化待发记录；运行进程保留最多一个尚未落库的候选批次。失败不替换 ID，重启后按可信租户清单加载持久化待发记录；并发实例发送相同记录由接收账本去重。收到明确成功后才删除待发记录。
- 尚在内存中的原始计数与未落库候选仍为 best-effort，进程崩溃可能丢失；不宣称业务事件到账单端到端 exactly-once。将业务事件与计量 Outbox 同事务写入留给后续独立批次。已停用/删除租户的待发记录保留，不越权做无租户扫描，后续需管理员核查。
- 独立客服→计费 HMAC 密钥，绑定有效期、固定受众/路径、租户和完整批次指纹。重放相同已认证批次只得到同一效果；篡改字段无效。只向客服/计费进程分发新密钥。模型不参与批次生成或签名。
- customer Outbox 使用 FORCE RLS、严格租户策略和显式 DML 授权；KB/平台角色无权读取。迁移由管理员执行，运行角色不执行 DDL。新建/升级共用同一 SQL，PR-7 再纳入权威版本管理。

## 验收与回滚

真 PostgreSQL、受限账号：并发重报、同键异内容、不同日期/批次、事务失败/回滚、隔租户、重启加载、落账成功但响应丢失。客户端验证业务 code，测试错误/过期/缺少签名、字段篡改和错误成功回执。未授权请求在写账本前拒绝。

部署先迁移，再同步更新发送/接收两端和密钥。不允许旧无批次协议继续累加。回退时停发送端、保留 Outbox/账本，使用兼容批次协议的版本；不能回退无认证和无去重协议、清空账本或给重试生成新 ID。无生产费用或性能收益承诺。
