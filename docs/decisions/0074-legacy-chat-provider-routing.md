# ADR-0074 旧客服 Chat 的租户供应商选择

意图识别、知识回答生成和 AI 质检共享一个路由入口。每次准备调用模型时，先以当前租户读取所选模型。配置读取使用 2 秒连接超时和 1.5 秒查询超时，并在异步入口通过工作线程执行。删除了 60 秒进程缓存，后续请求可读到已提交的新配置。

有效的租户配置使用记录中明确指定的供应商。空供应商和历史 `supportflow` 值保留已知模型家族的兼容解释。模型被停用、删除、供应商不受支持、所选密钥缺失或数据库不可读时，进入业务已有的本地处理。数据库成功确认租户没有活动选择时，才使用平台默认。平台显式指定的供应商也会在密钥缺失时进入本地处理。平台默认留空时延续现有的千问优先初始选择。

质检请求的 `provider` 和 `model` 可以确认现有路由，指定不同供应商或模型时进入本地规则。显式 `mock` 请求直接使用规则。供应商响应 429、5xx 或传输失败时，质检维持单次远程请求，意图识别走规则，知识问答沿用既有证据与拒答策略。模型选择诊断返回稳定判定码和当前来源。

## 验收与回退

- 在 `ai-service` 执行 `python -m pytest -q tests/test_chat_routing.py`。签名质检经实际接口连接本机的两个供应商夹具，验证选择、拒绝条件、请求次数和租户计量。
- 从仓库根执行 `python scripts/test-agent-runtime.py`，在隔离 PostgreSQL 上验收同名模型的租户归属及停用、删除、清除选择后下一次请求的变化。
- 应用无需数据库迁移。若要回退到旧版本，先按部署要求控制可用供应商凭据，旧版会恢复跨供应商自动回退。视觉、Embedding 和工单 Runtime 继续使用各自已配置的供应商。

供应商配置由部署方管理。本批覆盖旧客服 Chat 的单次选择和失败处理。供应商数据处理区域配置、按任务的明确备选授权和真实供应商对照仍待验收。
