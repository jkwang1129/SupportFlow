# ADR-0032 坐席审查授权边界

坐席通过既有的登录态和工单管理权限审查审批。租户与审查者引用来自后端认证上下文。客服服务以当前会话和已交付来源记录核对租户、来源事件及 Run，再用既有双服务签名调用 AI。审批应保留来源原文和有限工单提案供审查，审批文本不进入日志或普通状态列表。

先交付仅内部使用的 AI 审查协议。审查决定绑定已查看的审批 ID、来源事件、参数摘要、固定操作/版本和可信坐席引用。在 Run 行锁内重验这些字段，收到过期、已取消、已撤销或与所查看提案不一致的请求时返回固定错误。沿用客户服务的签名、方法、路径、正文和租户绑定，独立默认关闭。其他服务或模型不具备审查权。

随后接既有客服管理权限和窄接口。原工单业务服务继续核验当前会话、客户、短写许可及回执。验收包括匿名、非审批角色、跨租户和非当前来源、错误摘要、审批时接口失败、重复提交以及实际获批工单创建。回滚关闭审查入口并处置待审任务，保留原决定、工单及回执。

客服权限层只认可明确查询到的企业管理员或客服主管角色。原工单的历史租户兼容分支会把空角色当管理员，审批入口需要明确角色。Java 客户端还要接受 `WAITING_APPROVAL` 的重复投递确认，使旧 outbox 在已提交接收结果丢失后能结束重发。

客服接口 `POST /api/customer/agent-approvals/events/{eventId}/runs/{runId}/decisions` 在短事务内核验来源。批准要求会话仍可由 Agent 处理且原快照仍匹配。拒绝与撤销核对已交付的同租户事件和 Run，人工接管后仍可收回权限。结果只包含审批 ID 和状态。签名 RPC 在事务结束后执行，当前身份、审批与业务写入仍分别由客服、AI 和工单服务各自校验。

客服和 AI 开关均默认关闭。回滚先关闭客服审查入口，保留既有决定和回执。启用由人工审查的任务时，还需提供带权限校验的原提案预览以及已知来源的入口。
