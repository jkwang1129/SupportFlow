# ADR-0030 限时审批与运行恢复边界

PR-10 增加 `WAITING_APPROVAL`。首个集成以现有内部工单作为真实业务样本，对明确选择审批策略的宿主生效。审批权限沿用可信服务和坐席身份。模型只提出标题与正文，审批主体、作用域、用途及服务地址由宿主绑定。

按三个提交实施。

1. AI006 增加等待状态、审批记录和租户约束。复用原 Run/Step。每个审批绑定 Run、请求主体、唯一审批标识、工具及协议版本、来源快照、用途和精确参数摘要。有效期使用数据库时钟，并被原任务截止时间限制。审计保留请求、决定者、决定时间和消费步骤。先验证新旧库、历史数据与隔离权限。
2. Runtime 复用已原子落盘的步骤和正文检查点，在一个事务内绑定审批请求、清理租约并递增令牌。准备阶段中断可复用原检查点。待审批任务保持同会话顺序，其他会话继续领取。可信控制面决定通过、拒绝或撤销。重复决定不改变已记录事实。超时或拒绝结束等待并解除阻断。审批通过沿用原预算，恢复时重建原参数并再次校验当前来源与权限。
3. 对审批策略下的工单，写步骤预留与单次审批消费同事务。签发器核对该步骤、原批准参数、审批有效期和当前令牌，Java 则复用当前来源与业务回执校验。有界审批和写许可的竞态按实际提交时点处理；消费后结果未知时使用原核销流程。UI 和路由开关有各自的验收条件。

验收以真实 PostgreSQL 验证等待后重启、重复和并发审批、拒绝、过期、撤销、取消、不同租户或账号、修改标题或正文、来源撤权及已消费重放。用现有真实工单接口核对一张工单、一条回执与原预算。升级采用版本迁移和结构核对，回滚先关闭新审批入口并处理仍在等待的任务，保留批准和执行记录。

AI006 存储批次通过 18 项真实数据库测试、17 项迁移测试及 97 表结构核验。等待态已由数据库约束禁止持有租约。运行账号只可更新决定、关闭和消费字段。详细复现和服务结果见 [阶段验收](../reliability-verification.md)。
