# ADR-0064 整页刷新后按会话恢复工单任务进度

工作台打开工单审批时，先查活动提案。当前页面仍可按已知任务引用读取进度。整页刷新后，若当前会话没有活动提案和内存引用，调用 `GET /api/customer/agent-approvals/sessions/{sessionNo}/latest-progress`。查询依据当前登录坐席和当前选中的会话，无需在浏览器持久化任务引用。

客服服务先检查管理员或主管角色及会话当前资格。AI 按租户、会话和来源序号返回最近一个已批准且已终止的任务，沿用会话序号索引和租户行级策略。客服服务收到结果后核对租户、会话、已投递事件、Run 以及审批来源快照，并重新检查来源有效期和会话状态。页面只得到状态、执行轮数和步骤数。已拒绝、未获批和仍执行的任务留给原审批与进度入口。

来源快照过期、会话接管或标识不一致时停止展示。授权窗口沿用既有来源规则。刷新找到的终态只允许查看进度，提交决定或撤回仍依赖活动审批的原接口。

## 复现与回退

- JDK 25 下先运行 `mvn -B -f backend/pom.xml verify`，再运行 `python scripts/test-customer-rls.py --with-ai` 和 `python scripts/test-agent-runtime.py --with-java-delivery`。测试覆盖受限 PostgreSQL、签名查询、真实会话接管与来源过期。
- 从 `frontend` 运行 `npm run test:browser`，使用受控 HTTP 响应验证真实工作台整页刷新、重新选会话及恢复进度。
- 依次部署 AI、客服和前端。回退时先恢复原前端，再回退客服与 AI。无数据库迁移。状态恢复采用按需 HTTP 查询，任务事件续传独立验收。
