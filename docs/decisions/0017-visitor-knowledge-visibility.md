# ADR-0017：访客知识查询仅使用已发布且索引完成的文档

日期：2026-11-21。现有Java KbService已定义文档状态1草稿/2审核/3发布/4下线和索引状态1未索引/2索引中/3完成/4失败；发布操作要求索引完成。原AI检索只核租户/删除，不核发布，访客brain和旧chat直接用同一RAG。后台编写/检索测试与访客答复需要区分可见性。

复用现有检索链，增加仅供可信宿主选择的published_only布尔策略。访客brain/旧chat固定True，忽略用户问题或状态中的同名字段；后台问答/检索现有调用保持默认False，不新增可由用户/模型覆盖的访客请求字段。策略贯穿两种图、改写重检、retriever、内置/LlamaIndex、向量/关键词；与doc_ids求交。严格拒绝非bool参数。SQL在同租户JOIN/RLS/is_deleted上增加status=3 AND index_status=3，不新增表或授权体系。

这是查询时点的访客发布过滤，不是完整文档ACL/知识版本。没有持久化RAG结果缓存；下线、删除或索引状态改变后的新查询必须重新经过SQL。模型在途后的最终事实/权限核验、用户级文档授权、知识发布快照与Runtime工具仍需后续交付，不能声称跨服务即时撤回已发送模型上下文。后台预览仍只依赖其既有可信服务/租户授权，False不授予跨租户权限。

自动化验证：宿主固定策略/伪造状态、两图改写不丢策略、两引擎向量与关键词均保留范围+策略、错误类型在I/O前拒绝；真实受限KB角色PG覆盖草稿/审核/下线/索引未完成/失败/删除/异租户，并验证状态变化后新查询不再返回原资料。原业务正常路径和后台默认需回归。

新增Customer008迁移，只给既有受限KB能力组增加index_status列SELECT；不改已登记的历史003，不给整表/正文/文档修改权限，先migrate/provision/verify再启用新版AI。readiness也要求该列可读。007→008须保留原文档/切片/业务数据及全部发布状态；六库表数仍94。无Java/依赖/新框架改变；访客对尚未发布内容拒答/转人工是有意行为变化，原始数据保留。回滚应停止访客知识答复或转人工，不回退成向访客开放草稿；后台编写与既有Runtime/预算/回执不变。新知识工具仍须可信来源/当前资源授权及显式Embedding预算，不以本批代替它们。
