# ADR-0083 知识切片暂存与原子切换

Java 持有知识文档写事务，AI 在另一笔事务中完成切片写入。旧流程直接替换生效切片。如果 AI 已提交而 Java 未收到响应，正文和发布状态随 Java 回滚，检索却会命中新切片。

客服服务现在为每次索引分配 UUID，通过已有服务凭证调用 AI 暂存接口。文件和录入正文都使用现有切块和向量流水线。暂存表以租户、文档、尝试 UUID 和切片序号区分写入，无需读取尚未提交的新文档。AI 负责生成，Java 负责在文档事务中核对返回的文档 ID、正切片数和实际切换行数，并一并提交正文、索引状态和生效切片。删除旧切片、消费暂存行和写入新切片同事务执行，核验失败时统一回滚。

RAG 与预览继续读取生效表。AI 响应丢失或晚到时，未被 Java 提交的暂存行不会参与检索。重试分配独立 UUID。删除文档时清理已有生效和暂存切片。每次暂存写入最多清理本租户 256 条超过一天的暂存切片。长时间无写入的租户仍可能保留失败或晚到尝试，后续独立处理运维清理与备份保留。暂存表具备强制 RLS。客服账号可消费暂存行，AI 知识库账号可写入本租户暂存行。

部署顺序为执行 `customer_db` 010 迁移并验证，再更新 AI，最后更新所有客服节点。使用旧路径的客服节点仍采用原就地索引流程，生产切换应先暂停旧节点知识写入。回滚可先回退客服节点，再回退 AI，保留已应用迁移和已提交数据。避免回滚期间并行执行同一文档的知识写入。

在隔离环境执行 `python scripts/test-customer-rls.py --with-ai`、`python scripts/test-versioned-migrations.py` 及 `python scripts/test-database-init.py`。回归涵盖响应丢失、重试、切片数不匹配、关键词及向量检索和跨租户过滤。暂存以确认的切片作为提交条件，历史正式版本回滚与外部模型用量结算仍各自验收。
