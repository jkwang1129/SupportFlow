# ADR-0044 Runtime 模型用量回执

模型检查点会按原有策略过期并清理。单任务用量查询原先从这些检查点读取供应商用量，导致已观测的 Token 在清理后变为未知。AI 009 增加独立的 `agent_model_usage` 表，按租户、任务和物理步骤保留已核验的计数。

Chat 和 Embedding 共用原模型步骤的提交事务。供应商返回已知用量时，持久化输入 Token、适用的 Chat 输出 Token、原步骤围栏和摘要、检查点 ID 与摘要。正文、提示词、向量和凭据继续遵循原检查点的生命周期。重读成功步骤不触发 HTTP 请求或再次写回执。提交失败时回执、检查点和完成状态一并回滚，已有模型预留仍记作未观测用量。

运营查询保持原命令和结果格式。检查点仍有效时同时核对回执与检查点。检查点已清理时，通过原步骤的围栏、意图摘要和结果引用核对回执。已有任务缺少回执时仍可读取有效检查点，历史缺失和尚未观测的调用保持未知。供应商明确返回的零值保留为零。迁移不回填历史数据。

强制行级策略沿用 Runtime 租户上下文，应用角色只可追加和读取本租户回执。回执跟随任务保留，正文清理不删除回执。部署沿用 migrate、provision、verify。回滚应用代码时保留 AI 009 及回执，旧应用恢复检查点口径；数据库迁移包保留当前版本。该回执记录供应商已知 Token，租户额度预留、价格版本、金额结算和账单对账分别验收。
