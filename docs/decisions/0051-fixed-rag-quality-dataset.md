# ADR-0051 RAG 对照评测的固定样本和标注

`rag-quality-v1` 固定 15 份合成文档、25 个问题和基准日期 2026-11-23。样本覆盖两个虚构租户，包含 FAQ、多文档、上下文承接及切换、范围限制、发布与索引状态、证据不足、政策冲突、转人工和不可信内容。样本标注为 13 个回答、10 个拒答和 2 个转人工。已有 RAG 契约用例、工单故障回放基线和本地历史报告继续各自使用。[样本](../../fixtures/evaluation/rag-quality-v1.json)

## 标注口径

- `document_scope` 为 `null` 时使用租户授权文档，为 `[]` 时使用空集合。政策证据需要同时满足租户、范围、已发布、索引就绪和适用日期。`valid_until` 为排除边界。不可信回帖可作为测试检索输入，回帖内容不构成政策证据或授权。
- `expected.relevant_document_ids` 表示与问题相关的适用文档。一个拒答样本也标注了相关文档，因为该文档只给出发货时间，无法确认签收时间。回答样本的 `facts` 列出需要保留的事实、条件或单位，每条绑定文档 ID 和可逐字核对的原文片段。合理同义转述可通过事实评审。
- `abstain` 用于缺乏可用证据。`handoff` 用于政策要求人工核查或冲突无可适用版本。转人工标签描述应给出的决策，评测无需真正建单。`forbidden_markers` 是合成的越界输出检查点，测试还应通过文档 ID 和原文核对越界引用。
- 对照运行的输入只使用问题、历史、租户、范围和语料。`expected` 只交给评测器。传统 RAG 基线采用单次检索，Agentic RAG 使用现有图的路由和查询改写。两条路径复用同一语料和适用日期、模型和预算，分别记录代码、Prompt 和模型版本。后续样本版本应保留本版本和旧结果。

## 后续对照指标

| 指标 | 口径 |
|---|---|
| Recall@5 | 取排序最前的 5 个不同文档 ID，计算命中相关文档数除以该题相关文档数，对 16 道有相关文档标注的题求均值 |
| 回答正确率 | 13 道应答题中保留所有必要事实且无矛盾结论的比例，拒答和运行失败计入分母 |
| 引用有效率与覆盖 | 逐条核对已输出引用的实际文档和事实支持，另报应答题中含支持引用的覆盖率。无引用时有效率留空 |
| 拒答与转人工 | 报告全部样本的实际拒答率、应拒答样本命中率、应答样本误拒率，以及转人工准确率、精确率和召回率 |
| 延迟与 Token | 记录逐题端到端耗时并统计 P50/P95，另报调用次数和供应商用量回执完整性。缺失的 Token 留空 |

本批校验样本和标注的一致性。对照结果由后续评测运行产生。当前语料和标签使用 SHA-256 固定，摘要取 UTF-8、排序对象键、去除 JSON 格式空白后的内容。列表顺序参与摘要。修改内容时新建数据版本和对应摘要。CRLF 或 JSON 缩进变动独立于数据版本。
