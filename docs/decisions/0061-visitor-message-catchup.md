# ADR-0061 通过访客长连接补拉会话消息

访客 Widget 沿用已有的已认证 WebSocket。收到缺号消息时，在合并这条消息之前记录本地的游标。重连时保留已展示的消息及待确认气泡，合并重新进入会话返回的快照，再从断线前的已知位置补拉。收到已持久化的记录后按消息号合并，并用客户端消息号替换对应的待确认气泡，最后按服务端序号展示。

`SYNC` 由当前连接身份限定租户和会话，接收一个非负整数 `afterSeq`。实时服务通过原签名内部接口读取，固定为访客可见视图和每页最多 100 条。返回 `SYNCED`，包含请求游标、升序消息和下一页提示。Widget 每次等待一页，按返回的最后序号前进。批次结束时接受因内部备注形成的合法序号间隙。

## 复现与回退

- 从 `frontend` 运行 `npm run test:browser`，使用 Chromium 及受控 WebSocket 输入，覆盖接收顺序、续拉和未确认消息重发。
- 从仓库根目录使用 JDK 25 构建，运行 `mvn -B -f backend/pom.xml -DskipTests package`，再运行 `python scripts/test-security-flow.py`。后者使用隔离数据库及实际客服和实时服务，验证漏掉的机器人回复可读、内部备注不可见、跨会话和非法游标被拒绝。

发布时先升级实时服务，再更新 Widget。回退时先恢复旧版 Widget，再回退实时服务。沿用既有消息存储和幂等键，无数据库迁移。此批覆盖会话消息补拉。Agent 步骤事件与访客端工单结果展示单独验收。
