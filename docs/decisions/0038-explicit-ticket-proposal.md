# ADR-0038 由访客明确请求生成待审工单

单租户工单 Worker 可启用显式提案路径。原签名访客登记、不可变消息快照和实时会话授权为唯一输入来源。只有第一行恰好为 `/ticket-request` 的消息才能进入提案路径。第二行作为标题，其余作为正文。运营端和模型不代填内容。提案沿用原工具参数边界、检查点、审批有效期和审核员的业务权限。

由宿主管理且默认关闭。启用后普通消息仍走原只读规划。命令本身使用与只读规划相同的持久化步骤位置绑定版本、源快照和路由，避免在恢复时跨两种路径继续。生成提案过程只读业务来源并暂停，后续人工审批和专用 Worker 联合决定是否执行。审批和实际建单都保留原 Java 权限检查。新配置无需迁移数据库。停用前等待已领取任务结束，再停止生成新提案。待审任务仍可审核或按原有效期过期，已有记录保留。

设置 `SUPPORTFLOW_AI_RUNTIME_TICKET_PROPOSAL_ENABLED=true` 后启动原单租户工单 Worker，并按审批部署说明启用坐席审核。示例消息如下。实际有效期取五分钟和原任务截止时间中的较早者。

```text
/ticket-request
登录后无法查看历史工单
请协助检查历史工单列表为空的问题。
```

相比让模型从自由文本自行触发写意图，显式命令可用已有会话和来源契约完成可复现演示。自然语言提案选择和访客交互入口独立验收。
