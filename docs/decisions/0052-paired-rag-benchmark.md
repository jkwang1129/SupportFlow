# ADR-0052 单次检索与 Agentic RAG 的配对评测

两个配置共用 `rag.graph.ask()` 和同一张 LangGraph。`single_pass` 的查询改写预算为 0，`agentic` 使用现有默认预算 1。两者共用首轮查询、检索与判分机制、生成提示词、返回前的来源复核和引用校验。运行器逐题比较首轮查询及有序检索结果，发现差异时报告失败。外部 API 和线上默认调用方式保持兼容。底层线性实现同样遵守预算，离线基准要求安装真实 LangGraph。

## 测试环境与输入

- 每次启动一个临时 PostgreSQL 17 容器，应用仓库的 `customer_db` 迁移。管理员将 [固定语料](../../fixtures/evaluation/rag-quality-v1.json) 写入两个测试租户，每份合成文档作为一个切片。检索使用继承 `supportflow_kb_tenant` 的临时登录角色，运行项目已有的关键词 SQL、租户绑定及发布过滤。用 `as_of` 把到期和未生效的已发布文档映射为下线状态。该映射由评测语料装载器完成，线上发布规则保持原样。
- 对多轮题，两组把历史回合放在当前问题前面。范围为 `null` 时使用租户可见文档，为 `[]` 时直接拒答。文档和问题在进入 RAG 时不含标签。已发布的非权威回帖仍可被检索，因此能观察来源权限与事实可信度的差异。
- 两组使用同一内置关键词检索配置，关闭远端向量、生成请求及 LangSmith 跟踪。固定生成替身只从实际 Prompt 的第一个资料块复制首句并追加 `[1]`。它不读取答案或决策标注。答案中的条件、否定、时效、冲突处理及政策权威性需要独立做语义评分。

## 报告与门禁

逐题报告记录每一轮查询、来源、回答、引用、决策、节点、耗时和生成调用次数。配置中记录检索阈值、改写限制和样本摘要，环境中记录版本和关键源码 SHA-256。

| 指标 | 计算口径 |
|---|---|
| 文档 Recall@5 | 最后一轮前 5 个切片的文档 ID 与该题标注比较。一个文档固定为一个切片。仅对 16 道有相关文档标注的题求宏平均，运行错误以 0 计。 |
| 引用结构有效率 | 核对显示编号和该编号对应的已检索切片，验证文档、切片编号、原文与当前测试范围。语义上的证据支持留空。 |
| 拒答率与决策匹配 | 实际 `abstain` 除以全部 25 题，另报应拒答命中和应答误拒。决策匹配覆盖标注为回答或拒答的 23 题。知识问答图只返回回答或拒答，转人工准确率留空。 |
| 延迟及用量 | 两组顺序串行，每题交换先后。统计 25 个样本的最近秩 P50/P95。计时包括本地编排、数据库和固定生成替身。逐题记录实际调用数，供应商 Token 留空。 |

CI 门禁校验配置预算、空范围、首轮同输入与同检索结果、全部轮次的来源可见性、引用结构及执行错误。语料中的标签差异和禁用输出标记按题报告，语义门禁需用人工标注校准后再启用。生成替身的结果仅用于评测链路验证。真实模型、向量检索的收益及生产端到端延迟仍需专项实测。

## 复现与回退

启动 Docker 后在仓库根目录运行以下命令。需要能获取 `pgvector/pgvector:pg17` 镜像，已有本地镜像也可运行。原始报告输出到 `.local/verification/`，CI 上传至 `ai-test-reports`。

```powershell
python -m pip install -r ai-service/requirements-test.txt
python scripts/rag_quality_benchmark.py --output .local/verification/rag-quality-benchmark.json
python -m unittest discover -s scripts/tests -p 'test_rag_quality_benchmark.py' -v
```

回退本批可撤销运行器、测试、配套 CI 步骤和 `max_rewrite_rounds` 可选参数。评测结束会清理临时数据库。应用数据库无需回退。
