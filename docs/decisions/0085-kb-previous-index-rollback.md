# ADR-0085 保留上一版知识索引并支持一次回滚

一次成功的重索引原本会覆盖当前生效切片，已提交的旧正文与向量缺少恢复入口。Customer 012 添加一份按租户和文档存放的上一版快照。客服服务持文档写锁，在切换事务内保存替换前的就绪切片、向量、切片元数据和编辑正文。生成、核对或提交失败会一并回滚快照变更。文件导入的原正文可为空，回滚按原值恢复。

有企业知识库权限的成员先通过 `GET /api/customer/kb/documents/{id}/index/previous` 获取版本 UUID 和切片数，再向 `POST /api/customer/kb/documents/{id}/index/rollback` 提交 `{"versionId":"<UUID>"}`。回滚在文档写锁内核对版本和切片数，恢复正文及切片并消费快照，无需再次向量化。再次提交同一 UUID 或提交已被新索引替换的 UUID 返回业务码 `40901`。当前标题、分类、附件引用和发布状态沿用文档现值，已下线文档须显式发布才对访客可见。

历史切片表通过强制 RLS 限定客服租户，归档读写仅授予客服运行组。AI 检索使用生效索引表。成功替换更新快照，文档删除同时清理现版、暂存和历史索引。两张新表独立于原 `kb_version` 台账，升级保留现存记录。客服就绪检查要求可读的快照表结构。上线顺序为停止旧节点知识写入，执行 `customer_db` 012 迁移和验证，再发布客服节点。应用回退保留迁移登记和索引快照，回退前暂停同文档的并行写入。

在仓库根目录运行 `python scripts/test-customer-rls.py --with-ai`、`python scripts/test-versioned-migrations.py` 和 `python scripts/test-security-flow.py`。本批覆盖一个向后版本。长期历史、快照到期策略和生产发布操作需独立验收。
