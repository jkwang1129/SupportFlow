# ADR-0058 工单只读规划的受控回放

将工单规划的模型决策解析、证据选择、读取及报告前复读提取为线上和回放共用的函数。线上调用者继续提供持久化模型客户端、授权后的 `ToolExecutor` 和报告落库逻辑。回放只提供按序消费录制事件的内存回调，重建同一规划上下文并比较结果。[规划执行入口](../../ai-service/ai/runtime/ticket_loop.py)

## 录制内容与信任边界

- 组合验收在预定合成会话中录制实际模型协议请求的消息摘要、替身返回的决策和通过 Java 服务及工具校验后的工单号、状态、更新时间。撤权等稳定错误码可记录到对应读取位置。预期为实际 Worker 终态与已验证报告。录制由测试入口管理，生产 Run 继续采用原有检查点和元数据导出。
- 回放数据使用 `ticket-read-tape-v1`。每次模型调用核对消息摘要，读取核对槽位、工具版本和工单号，最终核对所有事件均已消费。报告比较原始预期的结果分类、错误码、工单状态和两类调用计数。规划版本、策略摘要、缺失、多余、顺序错误或调用输入变化均可让结果失败。
- 仅支持固定工单只读能力，线上参数模型仍校验工单号与参数类别。回放无 HTTP、数据库和工具写入连接，读取只返回已录制的投影。未观测的引用或写工具选项在回放里失败。报告仅保留可核验元数据。回放只重建一次规划尝试，真实重试、审批和鉴权仍由独立联调验证。

## 复现与回退

从根目录运行 `python scripts/test-agent-runtime.py --with-java-delivery`。CI 在真实 Java、Python 和隔离数据库的现有联调中录制四个合成案例，随后在独立目录以空业务配置启动回放进程。使用同一份录制文件从 `ai-service` 目录离线重跑。

```powershell
python -m ai.runtime.ticket_replay --suite ../.local/verification/runtime-ticket-read-replay-tape.json
python -m pytest -q tests/test_ticket_replay.py
```

回退本批恢复原规划函数位置并撤下测试录制入口，当前 Run 和检查点格式沿用原版本，数据库无需回退。[实施和验收](../reliability-verification.md#d15-工单模型与只读工具受控回放2026-11-23)
