# ADR-0086 知识检索排序对照

既有问答评测使用 PostgreSQL 关键词检索，本批单独量化排序差异。复用冻结的 25 题基准和 12 题留出集，各自在隔离 PostgreSQL 上载入原资料，每份资料一条切片。关键词和向量分别复用现有存储查询，各取至多 10 条候选。两条链路的租户、文档范围和发布就绪过滤一致。RRF 使用常数 60，将两个候选列表中的名次倒数加总，单路重复切片只计一次，按最高单路名次和切片 ID 打破同分。三组输出各取前 5 条。

召回、倒数排名和归一化折损累计增益均按有相关文档标注的题目做宏平均。重复文档只在首次出现时得分。对全候选列表检查租户、文档范围和发布条件，越界使 CI 失败。关键词与向量的调用顺序逐题交替。RRF 延迟按两次顺序数据库查询加本地融合计算，数据库计时含连接和返回处理，向量 API 耗时单列。这里比较原始排序，问答图的阈值、改写和生成由既有评测覆盖。

默认使用确定性的本地哈希向量进行离线契约验证。`--live-qwen` 通过现有有界传输调用 `text-embedding-v3`，各组共享同一套 1,024 维向量，明确空文档范围不发送向量请求。只发送冻结的合成文本，至多 10 次请求、每次 8,000 字节，出错即终止。报告记录供应商的 Token 回执和请求、向量摘要。

```text
python scripts/rag_retrieval_benchmark.py --output .local/verification/rag-retrieval-benchmark.json
python scripts/rag_retrieval_benchmark.py --live-qwen --output .local/implementation/rag-retrieval-live-new.json
```

本批仅将 RRF 纳入评测和 CI。真实向量试验中，它在基准集的召回与向量单路持平，排名更低且数据库查询更慢。留出集的三种排序指标均已达样本上限。正式切换还需要更大的独立语料、查询时向量耗时和实际部署负载数据。评测回退移除对应 CI 步骤，检索接口和数据库部署无需调整。
