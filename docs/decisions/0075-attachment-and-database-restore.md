# ADR-0075 六库与附件联合恢复演练

扩展现有六库恢复脚本。使用两个独立 PostgreSQL 实例和两个独立 RustFS 实例，创建测试专用私有存储桶。RustFS 演练镜像固定到验收过的摘要。数据库与对象都写入合成业务数据后暂停写入，再导出逻辑备份。源和目标使用独立卷及临时凭据。

对象归档按分页清点当前可见对象，将原对象键、字节数、MIME 类型和 SHA-256 写入清单。对象内容流式存入按序号命名的 ZIP 成员。恢复先检查目标存储桶为空，再校验整个归档和所有成员。每条对象用 S3 的条件写入，RustFS 实测同一键覆盖请求被拒绝。恢复完成后重新 GET 对象核对字节和元数据。失败目标保持隔离，使用新的空实例从原归档重跑。[S3 条件写入接口](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/put_object.html)

数据库恢复完成后核对活动附件引用的对象键、文件长度和 MIME 类型，并用发布知识文档、文件元数据和 pgvector 切片恢复一条关联查询。演练覆盖聊天图片、头像、知识文档和营业执照。当前存储桶的无引用对象也会保留，已软删除的文件行可以缺少对象。目标继续通过空租户、双租户和平台上下文下的附件元数据范围检查，并拒绝对象匿名读取。

## 运行与证据

- 在测试环境安装 `scripts/security/requirements.txt`，以 `python scripts/test-database-restore.py --with-attachments` 运行联合演练。省略参数时继续走六库恢复。CI 使用联合模式。
- 使用 `python -m unittest discover -s scripts/tests -p test_attachment_backup.py -v` 验证损坏归档、重复键、错误桶和现有目标等拒绝条件。
- 测量从开始备份对象和数据库逻辑归档，到归档就绪的耗时。恢复耗时从目标已就绪后开始，计入数据库、对象、受限账号和引用核验。负面检查和容器准备或清理由单独步骤完成。容器移除成功后输出汇总报告。

报告只保留计数、摘要和耗时。测量适用于停写的合成样本和已就绪的空目标。生产连续写入的跨介质一致性、历史对象版本及桶策略、加密与远端保留、WAL、实际恢复时间和恢复点目标仍需单独设计和演练。
