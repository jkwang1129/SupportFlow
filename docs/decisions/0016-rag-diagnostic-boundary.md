# ADR-0016：RAG 应用诊断与错误响应边界

日期：2026-11-21。复用既有日志/Trace，不新增观测服务。旧RAG/知识库路径会把问题前40～60字、文件名、原始异常或带异常正文的traceback写进应用日志；部分400/500响应也直接返回str(exc)。用纯合成问题、文件名、上游凭据标记和异常注入完成18项负面复现，不据此声称发生过生产泄露。

应用诊断保留Trace/租户/文档引用、文本长度/数量、检索模式/命中数/分数/耗时、固定错误码和异常类型；不记录问题原文、文件名或异常正文，不对所测异常记录exc_info。问答/知识库错误使用固定中文提示，解析错误仍400、其他处理错误仍500；检索失败保持error模式但error字段改为RAG_RETRIEVAL_FAILED。Embedding/Reader/关键词/无模型降级及成功业务输出保持。正常授权回答、引用、索引结果的文件元数据仍可返回给原调用方，没有把业务结果当日志删掉。

选择从日志调用处排除内容，而非新增字符串正则脱敏：后者难以可靠覆盖任意供应商异常、文件名和PII。异常仅取类型，不调用str/repr；已处理HTTP错误使用from None，避免主动拼接原异常链。诊断仍可通过Trace/资源引用、稳定错误类别定位，必要原始正文在其已有受控业务存储按权限/保留策略查询。

18项自动化用例覆盖问答/独立检索错误响应、解析400、正常请求日志、retriever固定错误、两引擎关键词/判分、远程与Llama Embedding失败、本地无模型回答、DB探活、两个诊断查询故障、索引API/两引擎成功及可选Reader失败。断言只针对ai.*应用logger及这些已处理响应，使用合成标记，不读取真实密钥。

适用边界：不是通用PII检测器，也未清理历史日志；第三方HTTP客户端、反向代理/访问日志、框架未处理异常、Java可选payload日志、其他AI模块、Trace/评测导出及模型上下文仍需M04/M07治理。Trace/租户/模型等元数据需保持可信且不携带正文。没有替换旧Embedding传输或补齐硬费用预算，不把日志修复当Model Gateway完成。

无SQL/Java/依赖/业务路由改变。回滚关闭新增知识工具接入并保持固定错误和最小诊断，不恢复原问题/异常正文输出；既有业务数据、Run/Step/回执和预算不回滚。400解析细节由原异常改为固定提示是有意收紧，调用方仍可据HTTP状态和Trace处理错误。
