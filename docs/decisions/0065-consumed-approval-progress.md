# ADR-0065 整页刷新后恢复已消费审批的执行进度

工作台继续先查当前可审批提案。整页刷新后，若没有活动提案与组件内任务引用，就按当前会话查询最近已审批任务的进度。复用 D21 的 URL、三字段响应与手动刷新。

AI 在原有已批准终态之外增加两种状态。只有持久化审批已被写入步骤消费时，查询才返回 `RUNNING` 或 `RETRY_WAIT`。消费发生在预留写入步骤的事务内，因此执行中状态只表示任务仍在处理。工单实际创建仍以业务回执为准。查询仍按来源事件序号选择最新记录，等待审批和待执行的获批提案继续走原入口。

客服服务沿用坐席角色、租户、会话、已投递事件和来源快照核验。工作台恢复时只读取执行状态，保留活动提案的操作权限和优先级。数据库结构、Worker 执行逻辑以及写入和重试规则沿用现有实现。

## 验收与回退

- 先运行 `mvn -B -f backend/pom.xml verify`，再运行 `python scripts/test-customer-rls.py --with-ai` 和 `python scripts/test-agent-runtime.py --with-java-delivery`。联调在真实 Worker 消费审批、发出写请求后且工单落库前读取进度。定向数据库测试从执行中跟踪至重试和完成。
- 在 `frontend` 运行 `npm run test:browser`。受控 HTTP 夹具驱动真实浏览器完成整页重载和手动刷新，覆盖执行中、等待重试和完成状态。
- 先升级客服服务，再升级 AI。旧版 AI 的终态响应可由新版客服服务读取。回退时先恢复 D21 的 AI，再恢复客服服务，随后恢复为仅按会话找回终态。无需数据库迁移。
