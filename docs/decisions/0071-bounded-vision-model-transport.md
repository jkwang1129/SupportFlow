# ADR-0071 视觉模型有界传输

客服服务仍将附件转换成 JPEG data URL。Python 视觉适配器继续按当前租户配置或平台默认选择模型，将文本和图片放入同一条多模态消息。客服识别结果保留 OCR、订单号、金额、摘要及人工建议。供应商返回纯文本时，现有摘要回退照常工作。

视觉调用复用 Chat 和查询 Embedding 的 HTTP 传输。每次只发送一个请求，连接、响应头和响应正文共享一次调用时限，固定配置的供应商地址禁用重定向和环境代理。保留现有图片张数和单张大小配置，默认 3 张、每张 data URL 至多 6 MiB。接受 JPEG、PNG、WebP 和 GIF 的 Base64 data URL，发送前检查格式与编码。视觉请求序列化后硬上限 19 MiB，响应上限 256 KiB。文本 Chat 和查询 Embedding 维持 256 KiB 请求上限。

合法的模型尝试以本次租户归属写入现有 AI 计量。正常结果传入供应商用量，故障记录失败元数据，发送前拒绝的输入不会触发供应商计量。暂时性供应商故障映射到 HTTP 503，其他供应商协议错误映射到 HTTP 502。HTTP 错误的对外正文沿用 AI 服务统一错误形状。客服 Java 的已有 AI 请求计数继续在转发前执行。

Python 视觉 API、编排与传输，以及 Java 视觉编排、客户端与图片消息处理，记录调用链、状态、时长或字符数。OCR、订单号、随图文字与供应商错误正文仍由原业务链路按既有用途处理，视觉诊断日志只使用元数据。计量写入故障按异常类型记录。

## 验收与回退

- 在 `ai-service` 中运行 `python -m pytest -q tests/test_vision_transport.py tests/test_chat_transport.py tests/test_internal_auth.py`。签名视觉接口把合成图片发往本机 HTTP 供应商，检查业务字段、错误状态、请求次数和计量归属。慢读和超限使用可控本地故障夹具。
- 使用 JDK 25 在仓库根执行 `mvn -B -f backend/pom.xml verify`。Java 测试覆盖签名视觉请求、保留业务字段、错误回退与日志。
- 视觉 API 的请求及成功响应格式兼容现有 Java 调用方，应用可分开回退。回退 Python 到上一版将恢复旧视觉调用行为及原有计量缺口，保留脱敏需单独回移日志改动。可保留独立的 Java 脱敏与 E11 预算闸门。应用变更无需数据库迁移。

测试夹具验证协议和错误处理。实际供应商兼容性、OCR 准确率和性能需在目标环境独立验证。
